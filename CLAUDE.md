## Architecture

Flat 3-layer architecture with no external state manager — `StreamBuilder` + `setState` throughout.

```
lib/
  main.dart               # App entry point: Firebase init, AdMob init, theme, auth routing
  firebase_options.dart   # Generated by FlutterFire CLI — do not edit manually
  models/                 # Pure Dart data classes (fromDoc/toMap, no business logic)
  services/               # All side effects live here (Firebase, Auth, PDF, notifications)
  screens/                # Full-page widgets, one per route
  widgets/                # Reusable sub-widgets
```

### Data flow

The root `StreamBuilder` in `main.dart` listens to `FirebaseAuth.authStateChanges()` and routes to `HomeScreen` or `LoginScreen`. All Firestore access goes through `GlicemiaService`, which scopes every query to the current user's `uid`. Screens call service methods directly — there is no intermediate ViewModel or Provider layer.

### Key services

- **`GlicemiaService`** — sole Firestore accessor. Paths: `usuarios/{uid}/registros`, `usuarios/{uid}/perfil/paciente`, `usuarios/{uid}/refeicoes`.
- **`AuthService`** — wraps `FirebaseAuth` + `GoogleSignIn`. Supports email/password, Google Sign-In, and password reset.
- **`NotificacaoService`** — local notifications via `flutter_local_notifications` + `timezone`.
- **`PdfService`** — generates PDF reports from `RegistroGlicemia` lists using the `pdf` package.
- **`AnalyticsService`** — thin wrapper around `firebase_analytics`; its `NavigatorObserver` is registered in `main.dart`.

### Authentication note

On first launch the app calls `signInAnonymously()` so users get immediate access. If they later sign in with Google, the anonymous UID changes and **existing data is not migrated**. To migrate, use `linkWithCredential` before completing the social sign-in.

### AdMob

`AdBanner` widget uses test IDs in development. Production IDs must be set in [lib/widgets/ad_banner.dart](lib/widgets/ad_banner.dart) before publishing. The banner only occupies space after a successful load (`_carregado == true`).

### Android release signing

The release build reads `android/key.properties` (gitignored). Structure:
```
storePassword=...
keyPassword=...
keyAlias=...
storeFile=path/to/keystore.jks
```

### Firestore security rules

Current rules (`firestore.rules`) allow any authenticated user to read/write any document. Tighten to per-user paths before expanding user base.
